# Auditoría de secretos e identidades — 2026-10-26

Ticket: *Audit WarpMetal identity and vault secret handling against the Railway exposure model.*

## Alcance y método

Modelo de amenaza de referencia: el 21 de octubre Railway detectó acceso no autorizado a variables
de entorno de clientes y, en algunos casos, a su contenido ya descifrado. La lección no es que falte
cifrado, sino que el cifrado en reposo no cubre a un atacante que **ya alcanzó el servicio**. Esta
auditoría pregunta, para WarpMetal, qué material sigue protegido cuando el atacante puede leer el
host: el directorio de configuración, el entorno y el argv de los procesos del mismo usuario, el log
de auditoría y los artefactos que se copian (backups, tarballs, commits).

Código auditado:

| Repo | Commit | Rama |
|---|---|---|
| `skills` (CLI `@warpmetal/cli` 0.1.0) | `d0e224a` | `feat-gatewayTools` |
| `warpmetal-mcp` (0.3.0) | `8144dfb` (+ cambios sin commitear de empaquetado) | `main` |

Método, sin escrituras sobre archivos versionados:

1. Lectura estática de todo el camino del secreto: selección de backend, cifrado, emisión,
   redacción, spawn de hijos y log de auditoría.
2. Sonda ejecutada contra el redactor real (`redact()` sobre payloads representativos), para no
   confundir lo que el código *dice* con lo que hace.
3. Replay de los fixtures del servidor MCP para ver qué campos cruzan el envelope.
4. Suites existentes como línea base: `packages/warpmetal-cli` → **6422 tests, 0 fallos**
   (`npm test`, 2026-10-26).

Fuera de alcance por diseño: el paquete upstream `warpmetal@0.8.12` (se consume, no se parchea),
la implementación de KMS, la revocación del lado del proveedor y el servidor del vault remoto.

## Lo que ya está probado (no re-auditar)

- Cifrado y formato: AES-256-GCM, scrypt N=2¹⁵ r=8 p=1, AAD `warpmetal-env:v1`, `0600`/`0700`,
  write-then-rename, error indistinguible entre passphrase mala, llave ajena y ciphertext
  manipulado ([file.ts](../../packages/warpmetal-cli/src/env/backends/file.ts),
  [vault.test.ts](../../packages/warpmetal-cli/test/vault.test.ts)).
- No existe acceso bulk al vault: la API sólo expone nombres, y hay un test que prohíbe
  `values`/`dump`/`payload` en la superficie del store
  ([store.ts:128](../../packages/warpmetal-cli/src/env/store.ts:128),
  [vault.test.ts:64](../../packages/warpmetal-cli/test/vault.test.ts:64)).
- Un secreto no entra por argv ni sale por JSON: `env store set` sólo acepta `--stdin`/`--from-env`,
  `env secret` exige `--stdout` y rechaza `--json`
  ([secret.test.ts](../../packages/warpmetal-cli/test/secret.test.ts)).
- `privateKeyPath` se redacta en `data` y en el canal de texto, y `redacted[]` nombra el campo sin
  nombrar el valor ([conformance.test.ts:1205](../../../warpmetal-mcp/test/conformance.test.ts:1205)).
- El servidor MCP nunca abre una clave privada: los campos de ruta se validan por forma y se pasan
  al CLI como cadena ([schemas.ts:11](../../../warpmetal-mcp/src/schemas.ts:11)).
- El log de auditoría no escribe argv ni valores: sólo tool, subcomando, código de salida, estado,
  duración y **nombres** de campos redactados ([audit.ts:177](../../../warpmetal-mcp/src/audit.ts:177)).

## Reproducción

```sh
# F-01: el keychain no está instalado ni declarado
npm --prefix packages/warpmetal-cli ls @napi-rs/keyring
node -p "require('./packages/warpmetal-cli/package.json').optionalDependencies"

# F-02: ningún spawn fija el entorno
grep -n "spawn(" packages/warpmetal-cli/src/run.ts packages/warpmetal-cli/src/upstream.ts
grep -n -A5 "spawn(target.command" warpmetal-mcp/src/exec.ts

# F-03/F-04: la sonda contra el redactor real
node -e "import('./warpmetal-mcp/dist/src/audit.js').then(m=>console.log(

  packages/warpmetal-cli/test/vault.test.ts
```

## Cierre (estado tras las fases 2–4)

| ID | Estado | Cambio |
|---|---|---|
| F-01 | Corregido | `@napi-rs/keyring` pasa a `optionalDependencies`, así que el keychain es alcanzable en una instalación normal; el file backend ya no crea `vault.key` sin aceptación. |
| F-02 | Corregido | `childEnv()` en CLI y MCP construye un entorno explícito sin passphrase, token ni wallet password; un override no puede reintroducirlos. |
| F-03 | Corregido | `wm_server_identity` y `wm_identity_list` proyectan el payload a `keyName`/`sshFingerprint`/`serverId`/`hasLocalKey`; ningún campo `*Path` llega al cliente. |
| F-04 | Corregido | El redactor clasifica por **valor**: una cadena que es entera una ruta absoluta se convierte en `[REDACTED:path]` sin mirar el nombre del campo. |
| F-05 | Aceptado | Las rutas siguen en argv de los comandos que las necesitan; no se registran ni se ecoan. Documentado en el threat model. |
| F-06 | Corregido | `scrubText` reconoce rutas bajo el home (`/home`, `/Users`, `C:\Users`, `/root`) y las redacta en errores y warnings. |
| F-07 | Corregido | `destroy()` borra `vault.key` siempre, incluido el caso con passphrase. |
| F-08 | Aceptado | `session.json` sigue siendo un bearer local; ahora `env status` reporta `keySource` y el threat model lo trata como secreto. |
| F-09 | Abierto | Windows: los `0600` no se aplican y la ACL no se verifica. Declarado como riesgo residual. |
| F-10 | Abierto | El directorio de auditoría se crea con el modo por defecto. El archivo sigue en `0600`. |
| F-11 | Aceptado | `env status` imprime la ruta del vault; es información que el operador necesita. |
| F-12 | Abierto | `plansDir`/`shimsDir` siguen declarados y sin uso. |

Pruebas que sostienen el cierre: `packages/warpmetal-cli/test/key-material.test.ts`,
`test/leak.test.ts`, `test/vault.test.ts`, `test/secret.test.ts`, y
`warpmetal-mcp/test/conformance.test.ts` (proyección de identidad, redacción por valor y auditoría sin
rutas). Suites: CLI **6432 tests, 0 fallos**; MCP **123 tests, 0 fallos** (2026-10-26).

## Limitaciones de esta auditoría

- No se ejecutó nada contra un host real comprometido: el análisis es estático más sondas locales.
- El `session.json` lo escribe el customer CLI, que no vive en estos repos: su modo de creación no se
  pudo verificar aquí y queda como supuesto (F-08).
- La revisión se hizo sobre árboles de trabajo, uno de ellos con cambios sin commitear
  (`warpmetal-mcp`); el commit citado es el último común, no necesariamente el estado exacto.
